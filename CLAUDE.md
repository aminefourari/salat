# Salat

Prayer-times monorepo (npm workspaces):

- `apps/web`: PWA (TanStack Start + React), deployed as one Cloudflare Worker (`salat`). Tabs: times, Quran, adhkar, Qibla, settings.
- `apps/macos`: native SwiftUI menu-bar app (adhan + Quran + adhkar), local/unsigned. Installed at `/Applications/Salat.app`. The project always stays free (the bundled adhkar content is "free, not for sale").

Specs: `docs/superpowers/specs/` (PWA: `2026-11-08-salat-pwa-design.md`, Mac: `2026-11-09-salat-macos-design.md`). Plans: `docs/superpowers/plans/`.

## Commands (from repo root)

- `npm run dev`: web dev on :3000 (Vite + workerd via `@cloudflare/vite-plugin`)
- `npm test`: Vitest (`apps/web/test`), incl. the shared parity fixture check
- `npm run build` / `npm run deploy`: build, then `wrangler deploy` (runs in `apps/web`)
- `npm run db:migrate`: apply `apps/web/migrations/` to remote D1 `salat`
- `cd apps/web && npx wrangler secret put VAPID_PRIVATE_KEY`: push signing key (never commit it)
- `npm run mac:build` / `npm run mac:test`: XcodeGen + xcodebuild → `apps/macos/build/Salat.app` / Swift tests
- `TEST_RUNNER_SALAT_LIVE=1 npm run mac:test`: also runs the live quran.com download test
- `apps/macos/scripts/fetch-assets.sh`: regenerate bundled Quran text, fonts, adhans and adhkar (outputs are committed); `fetch-adhkar.py` prints the AR/EN↔FR pairing report
- Install: `npm run mac:build && ditto apps/macos/build/Salat.app /Applications/Salat.app` (quit Salat first)

## Structure

- `apps/web/src/lib/`: isomorphic, pure code shared by browser and Worker (prayer math, methods, schedule, i18n)
- `apps/web/src/server/`: Worker-only code (push sending, cron, Habous timetable in `habous.ts`, served at `/api/habous`, used by the times page and cron for Morocco with the standard Asr)
- `apps/web/src/server.ts`: Worker entry (`fetch` from TanStack Start + `scheduled` cron)
- `apps/web/src/routes/`: file-based routes; `src/routes/api/*` are server routes
- `apps/web/public/`: manifest, service worker `sw.js`, icons
- `apps/web/test/`: Vitest tests; `fixtures/aachen-2026.json` is the Islamic Center Aachen 2026 timetable
- `fixtures/parity.json`: prayer/country cases generated from the web code, checked by both apps
- `data/quran.json`, `data/adhkar.json`: Quran text and Hisn al-Muslim adhkar shared by both apps (web loads them lazily via `?url` imports; Mac bundles them). Regenerated by `apps/macos/scripts/fetch-assets.sh`
- `apps/web/src/lib/{quran,adhkar}.ts`: pure reader logic mirroring the Swift `Quran/Recitations.swift` and `Adhkar/Adhkar.swift`
- `apps/macos/Salat/UI/Theme.swift`: the website's look (royal green and gold, Reem Kufi/IBM Plex Sans Arabic, star lattice, mihrab arch) in light and dark
- `.github/workflows/`: `ci.yml` (web + Swift tests on push/PR), `release.yml` (tag `v*` → GitHub Release with unsigned `Salat-vX.zip`)
- `apps/macos/Salat/Core`: Swift ports of methods/prayer math, scheduler, strings, settings
- `apps/macos/Salat/{Services,Quran,Adhkar,UI}`: location, adhan alerts, Quran reader/player, Hisn al-Muslim adhkar (text + cached audio), SwiftUI views
- `apps/macos/Widget`: WidgetKit extension (sandboxed). It computes nothing: `AlertEngine` writes `~/Library/Application Support/Salat/widget.json` (`Core/WidgetData.swift`) and the widget reads it through a read-only sandbox exception (no App Group without a signing team). Entitlements live in `project.yml`; XcodeGen rewrites the `.entitlements` file
- Mac updates: `Services/Updater.swift` asks the Worker's `/api/update` (`server/update.ts`, the latest GitHub Release with its asset SHA-256), downloads `?v=X.Y.Z` through the Worker, checks SHA-256 + `codesign --verify` + bundle id/version, then a detached `sh` swaps the bundle after the app quits and relaunches it. A release (tag `vX.Y.Z`) is what users get; the asset must be named `Salat-vX.Y.Z.zip`
- `apps/macos/project.yml`: XcodeGen spec (no `.xcodeproj` committed). The test target compiles the pure sources directly (no app host); add new pure files there too.
- `apps/macos/Salat/Resources/ATTRIBUTION.md`: licenses of the bundled Quran text, font, adhans, borders, cities

## Conventions

- Prayer times are always computed through `computeDay` in `apps/web/src/lib/prayer.ts` (web) and its Swift port `computeDay` in `apps/macos/Salat/Core/PrayerCalc.swift`. They must agree to the minute.
- Parity rule: changing `methods.ts`/`paramsFor` → port it to `Core/Methods.swift`, then `UPDATE_MAC_DATA=1 npm test` (regenerates `fixtures/parity.json` and the Mac's borders/cities resources) and `npm run mac:test`.
- Per-country method config is data in `methods.ts` / `Methods.swift`; adding a country is one entry in each.
- Times are formatted in the device's/subscription's IANA time zone, never UTC.
- User minute offsets (`adjustDay` / Swift `adjustDay`) apply after `computeDay` or Habous, never inside it, so parity fixtures stay pure.
- Reminder kinds (`lib/schedule.ts` `dayEvents`, Swift `Scheduler.swift` `Extras`) are the same in both apps: prayer start, 10 min before, adhkar (Fajr/Asr + 20 min, chapter 27), Friday Kahf (sunrise + 1 h) and Jumuʿah (Dhuhr − 45 min).
- Morocco (method `morocco`, standard Asr): official Habous times, imported once per month from habous.gov.ma into D1 (`habous_times`, `server/habous.ts`) and served by the Worker's `/api/habous?month=` (clients fetch a month and keep it) (web `useDays`, cron, Mac `AlertEngine` + `Core/Habous.swift`); the 19°/17° calculation is the fallback.
- No accounts, analytics, or third-party client calls. Exceptions (audio only): recitations from quran.com (`api.quran.com`, `download.quranicaudio.com`) and adhkar audio from `www.hisnmuslim.com`. The Mac app caches them offline; the website streams them directly from the browser (user decision).
- UI changes on the Mac: check them with `Salat.app/Contents/MacOS/Salat -snapshot DIR` (renders the menu and each window section: times, Quran, adhkar, in dark and light) and refresh `docs/screenshots/`.
