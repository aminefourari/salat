## Findings considered and rejected

- **Cron scans every row each minute, makes per-row D1/Habous calls, sends serially, and overlapping runs could
  double-send**: fine at today's handful of devices. The `ponytail:` comment in `server/cron.ts` already names the
  upgrade (`next_due_at`). Revisit at hundreds of subscriptions.
- **Rate limiting `/api/subscribe` and `/api/test-push`**: a Cloudflare WAF rule, not code. Do it once 002 lands.
- **Stale Habous response overwriting a newer place (web `useHabous`, Mac `refreshHabous`)**: heals itself on the next
  render or tick.
- **Mac settings reset when decoding fails**: only triggered by a downgrade, and the updater never downgrades.
- **Widget array bounds**: the app and widget ship in one bundle, so the formats can't diverge.
- **`.authorizedWhenInUse` not accepted on macOS**: speculative. macOS reports Always.
- **Empty `content-length` on the update zip; lazy route chunks not precached**: low confidence. The second is
  covered by 005's transitive precache anyway.
- **Validating the shape of localStorage settings, lint/format tooling, the per-second Mac tick, `AdhanStore`
  directory listing**: low value for the cost.
- **Type-checking `public/sw.js`**: the file is small. 005 adds a Vitest check of its pure parts instead.
- **Ed25519 signing as a must-do**: downgraded to a decision (016). With the key in the same GitHub repo, it only
  removes Cloudflare from the trust root.
