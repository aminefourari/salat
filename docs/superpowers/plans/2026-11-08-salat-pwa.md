# Salat PWA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Installable prayer-times PWA that computes times from GPS, shows Qibla, and pushes a notification at each prayer and 10 min before, on every subscribed device.

**Architecture:** One TanStack Start app deployed as a single Cloudflare Worker. Times are computed by one shared pure module (`src/lib/prayer.ts`) used by both the browser (display) and the Worker cron (scheduling). Subscriptions live in D1; a once-a-minute cron sends due Web Push messages with VAPID.

**Tech Stack:** TanStack Start (`@tanstack/react-start`) + React, Vite + `@cloudflare/vite-plugin`, Wrangler, D1, `adhan@4.4.3`, `@rapideditor/country-coder` (offline coords→country), `@pushforge/builder` (Web Push on WebCrypto), Vitest.

**Spec:** `docs/superpowers/specs/2026-11-08-salat-pwa-design.md`

## Global Constraints

- Cloudflare only (Workers, D1, cron triggers). The user's account is operated through wrangler; dashboard steps go through the browse MCP.
- Languages `ar` | `en` | `fr`; `ar` renders `dir="rtl"`. One setting drives the UI and the notifications.
- Notification copy: start `"It's time for {prayer} — {HH:mm}"`, reminder `"{prayer} in 10 minutes — {HH:mm}"` (translated).
- Germany: Fajr 18°, Isha 17°, `HighLatitudeRule.TwilightAngle`, adjustments `{ sunrise: -7, dhuhr: +5, asr: +4, maghrib: +7, isha: -3 }`.
- Morocco: official Habous timetable for the nearest city; fallback Fajr 19° / Isha 17°, labelled "approximate".
- No accounts, no analytics, no third-party calls from the client beyond our own Worker.
- Times are formatted in the subscription's/device's IANA time zone, 24h `HH:mm`.

## Review Focus

- Travel across time zones: the stored `tz` must update with location; the cron must format and pick the date in the subscription's `tz`, not UTC. → test in Task 3 (`dueEvents` in `America/New_York`).
- DST change days (Europe/Berlin last Sunday of Oct/Mar): no duplicate or skipped notifications. → test in Task 3.
- Missed cron minutes / duplicate cron runs: an event fires exactly once if it falls in `(lastSentAt, now]` and is no older than 5 min. → test in Task 3.
- Geolocation denied or unavailable: the app shows a clear message plus retry and keeps the last saved location. → Task 5 manual check.
- Expired push subscription (404/410): row is deleted, cron continues with the other rows. → test in Task 4.
